The vanilla client can be used with any frontend setup. It's perfect for:

- Backend-only auth setups (Bun.serve, Elysia, etc.)
- Frameworks not yet supported by `gau`
- Frameworkless apps

<br />

<Steps>
1. ##### Set up your backend

    Follow one of the backend-only integration guides:

    <IconLinkGroup>
      <IconLink href="/integrations/bun-serve/" icon="logos:bun" title="Bun.serve" />
      <IconLink href="/integrations/elysia/" icon="local:elysia" title="Elysia" />
    </IconLinkGroup>

    Or use `createHandler` from `@rttnd/gau/core` with any framework that supports standard `Request`/`Response` objects.

2. ##### Create the client

   Import `createAuthClient` and initialize it with your auth API base URL:

   ```ts title="src/auth.ts"
   import process from 'node:process'
   import { createAuthClient } from '@rttnd/gau/client/vanilla'
   import type { Auth } from './server/auth'

   export const auth = createAuthClient<Auth>({
     baseUrl: process.env.AUTH_BASE_URL, // http://localhost:3000/api/auth in dev
   })
   ```

   <Aside type="note">
     The `Auth` type import is optional but provides better types for your configured providers.
   </Aside>

3. ##### Use the client

   The client provides methods to manage authentication:

   ###### Fetch Session

   ```ts
   const session = await auth.fetchSession()
   console.log(session.user) // User | null
   ```

   ###### Sign In

   Redirects to OAuth provider

   ```ts
    window.location.href = await auth.signIn('github', {
     redirectTo: '/dashboard', // Optional
   })
   ```

   ###### Sign Out

   ```ts
   await auth.signOut()
   ```

   ###### Link Account

   ```ts
    window.location.href = await auth.linkAccount('google', {
     redirectTo: '/profile',
   })
   ```

   ###### Unlink Account

   ```ts
   await auth.unlinkAccount('google')
   ```

   ###### Refresh Session

   ```ts
   await auth.refreshSession()
   ```

   ###### Use a Server Session

   Start with the safe session returned by your server helper:

   ```ts
   const auth = createAuthClient({ baseUrl: '/api/auth', session })
   ```

   After navigation, apply fresh server data with `auth.setSession(session)`. This updates subscribers without making a request. To fetch current data from the server instead, use `auth.refreshSession()`.

   Create shared clients only in browser code. On the server, keep each visitor's session separate.

   ###### Listen to Session Changes

   ```ts
   const unsubscribe = auth.onSessionChange((session) => {
     console.log('Session updated:', session)
     // Update UI, store in state management, etc.
   })

   // Later: clean up listener
   unsubscribe()
   ```

   ###### Handle Redirect Callbacks

   After OAuth redirects back to your app, handle the callback:

   ```ts
   const handled = await auth.handleRedirectCallback((url) => {
     window.history.replaceState({}, '', url) // Example
   })

   if (handled) {
     console.log('OAuth callback handled, session updated')
   }
   ```

#### Session Token Storage

For browser apps that use bearer tokens instead of session cookies, set `credentials: 'omit'`:

```ts
const auth = createAuthClient({
  baseUrl: 'https://auth.example.com/api/auth',
  credentials: 'omit',
})
```

Use the server's default `session.strategy: 'auto'` or `'token'`. Add the frontend host to `trustHosts` and allow its origin in CORS. Use an absolute frontend URL for `redirectTo` when the backend is on another origin.

Browser sign-in uses PKCE and stores the returned bearer token in `localStorage` under `__gau-session-token`. Call `handleRedirectCallback()` after returning to the app; framework providers do this on mount. Bearer-authenticated requests omit cookies.

Bearer account linking requires the adapter's atomic `verification` store, supported by the built-in memory and Drizzle adapters. Navigate to the URL returned by `linkAccount()` promptly: it is single-use and expires after one minute.

#### API Reference

##### `createAuthClient<TAuth>(options)`

Creates a new auth client instance.

**Options:**

- `baseUrl` (required): Base URL of your auth API
- `credentials`: Fetch credentials mode; defaults to `'include'` in browsers and `'omit'` in Tauri

**Returns:**

- `fetchSession()`: Fetches the current session from the server
- `refreshSession()`: Fetches the session, updates client state, and notifies subscribers
- `applySessionToken(token)`: Applies a session token manually
- `onSessionChange(listener)`: Subscribes to session changes, returns unsubscribe function
- `handleRedirectCallback(replaceUrl?)`: Handles OAuth redirect callbacks
- `signIn(provider, options?)`: Initiates sign-in flow
- `signOut()`: Signs out the user
- `linkAccount(provider, options?)`: Links an additional OAuth account
- `unlinkAccount(provider)`: Unlinks an OAuth account
